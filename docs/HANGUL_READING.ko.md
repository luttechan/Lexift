# 한글 발음 → 일본어 후보

실제 사용 방법과 지원 범위는 [README_1.0.ko.md](README_1.0.ko.md)를 참조하세요. Caps Lock + A는 다른 앱에서의 변환 모드를 켜고 끕니다.

## 처리 흐름

현재 편집 입력란의 커서 앞 한글 발음 → 음절 규칙으로 가나 독음 생성 → 상주하는 별도 IME 문서에서 Microsoft 일본어 후보 생성 → 커서 아래 후보창 → 선택 시 해당 발음 범위 치환.

입력 감지와 치환은 UI Automation, 후보 추출은 TSF 후보 인터페이스와 소유 문서의 IMM 후보 정보를 사용합니다. 전역 키보드 후크에서는 문자열 변환이나 COM 호출을 하지 않습니다. 앱의 텍스트 접근 인터페이스를 이용하므로 접근성 지원이 없는 입력란에는 별도 대응이 필요합니다.

## 발음 규칙

현대 한글 11,172개 음절을 초성·중성·종성으로 분해합니다. 요음, 촉음, 장음을 처리하고, 현대 분해형 자모도 조합합니다. ㄴ·ㅁ·ㅇ 받침은 ん, 파열 받침은 っ, ㄹ 받침은 る로 근사합니다. 어·으·의·외 등은 가까운 일본어 소리로 근사합니다.

`와타시 → わたし`, `니혼고 → にほんご`, `갓코우 → がっこう`, `쿄우 → きょう`, `코-히- → こーひー`를 처리합니다. `아리가토`, `곤니치와`, `도쿄`, `오하요` 등 일부 관용 표기는 작은 보정 사전을 거칩니다. 모든 모음 길이나 문법을 자동으로 추론하는 번역 기능은 아닙니다. `와타시와`는 소리대로 わたしわ가 됩니다.

`모노즈쿠리 → ものづくり`, `츠즈쿠 → つづく`, `치지무 → ちぢむ`, `하나지 → はなぢ`는 관용 철자를 보정합니다. `ず/づ`, `じ/ぢ`, 장음, 한글 표기 변형을 비용과 중복 제거를 적용한 최대 16개 독음으로 구성하고, 각 독음을 실제 IME에 조회합니다. `쯔키`와 `츠키` 모두 `つき`를 지원하며, 청음·탁음의 대안은 기본 입력보다 낮은 우선순위입니다.

`치지마리마스 → 縮まります`, `치지마리마시타 → 縮まりました`, `치지마라나이 → 縮まらない`, `치지맛타 → 縮まった`, `치지메마스 → 縮めます`처럼 어간의 철자 보정을 활용형 전체에 적용하고, 실제 활용형의 한자 변환은 IME가 수행합니다. 모든 일본어 어휘를 완전하게 분석하는 형태소 분석기를 내장한 것은 아닙니다.

붙여 쓴 발음에는 조사 `わ/は`, `え/へ`, `お/を`의 대안을 만듭니다. 알려진 단어 경계와 일부 술어 앞의 조사 해석을 우선하되, 원래 독음도 남깁니다. `와타시와가쿠세이데스 → 私は学生です`, `니혼고오벤쿄-시마스 → 日本語を勉強します`, `도쿄에이키마스 → 東京へ行きます`를 실제 IME로 검사했습니다. 직접 조회에 전달된 공백은 경계 힌트로 사용합니다. 외부 앱의 자동 감지는 기존 한국어 본문을 함께 치환하지 않도록 공백으로 구분된 현재 발음 단위만 읽습니다.

독음 후보를 즉시 먼저 표시하고, 첫 IME 응답부터 화면에 반영합니다. 추가 독음은 같은 요청의 중간 응답으로 보강하며 완성된 결과만 캐시합니다. 입력 변경 시 오래된 응답은 무시하고, 사용자가 명시적으로 선택한 후보만 문자열 기준으로 유지합니다. 자동 미리보기의 첫 행은 새 한자 목록의 중간 행으로 따라가지 않으며, 새 입력의 목록은 1번부터 표시합니다. IME 후보가 문장 중 한 문절에 해당하면 전체 조합 문자열의 나머지 부분을 보존해 전체 입력 후보를 구성합니다. 후보별 조회 독음도 함께 전달합니다. 한자 후보 문자열과 순서는 설치된 IME 및 사전·학습 상태에 따라 달라집니다. 한자 후보를 고정 예시 목록으로 대체하지 않습니다.

## 대시로 장음 입력

한글 발음의 `-`는 앞 음절의 장음으로 해석합니다. `코-죠- → こうじょう → 工場·向上`, `도-쿄- → とうきょう`, `센세- → せんせい`, `수-가쿠 → すうがく`를 지원합니다. e열은 `い/え/ー`, o열은 `う/お/ー`의 대안을 조회하며, `오-키이 → おおきい → 大きい`, `오네-상 → おねえさん → お姉さん`도 처리합니다. 기존 `코-히- → こーひー`와 직접 입력한 가나의 기본 독음은 유지합니다.

`test-results/structural-query-final.json`은 실제 IME 18개 사례의 첫 응답·목표 후보·전체 검색 완료 시간을 구분해 기록합니다. 최초 가동이나 긴 문장의 한자 조회가 항상 0.1초 이내라고 보장하지 않습니다. 독음 미리보기와 추가 독음 조회를 분리해 후보 보강이 첫 표시를 막지 않게 했습니다.
