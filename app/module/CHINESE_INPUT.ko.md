# Lexift 1.0.1 한글 발음 → 중국어

Caps Lock + C로 한–중 변환을 켜고, 메모장 등의 입력란에 한글로 중국어 발음을 입력합니다. 커서 아래에서 후보를 고르면 원래 입력란의 발음 부분만 중국어 간체로 바뀝니다. Caps Lock + A는 한–일 변환입니다. 다른 언어 모드를 켜면 이전 모드를 종료하며, 같은 단축키를 다시 누르면 OFF가 됩니다. 설정에서 세 단축키를 바꿀 수 있고 중복은 저장할 수 없습니다.

한국어 IME가 한글 모드일 때만 단축키로 변환을 켤 수 있습니다. 영어 모드·일본어/중국어 IME·상태를 확인할 수 없는 입력란에서는 켜지지 않으며, IME를 강제로 변경하지 않습니다. 이미 켜진 변환을 끄는 동작은 다른 입력 상태에서도 가능합니다. 중국어 IME나 인터넷 연결은 필요하지 않습니다. 한국어 문장의 의미를 번역하는 기능은 아닙니다.

## 병음 분류와 한글 입력

`pinyin_phonetics.py`는 성모·운모를 먼저 분류한 다음, 한글로 받아들일 발음 형태를 생성합니다. 사전에 실린 415종 병음 음절에 대해 생성 결과를 검사합니다. 모든 성모와 운모를 무조건 조합하지 않으며, 실제 후보는 병음 사전에 존재하는 음절과 단어에서 만듭니다.

| 분류 | 처리 | 한글 입력 예 |
|---|---|---|
| 무기음·유기음 | b/p, d/t, g/k, j/q를 분류하고 한국어 평음·경음 표기를 별도 비용으로 허용 | 베이/뻬이, 따, 까오 |
| 설면음 | j/q 뒤에서 이미 구개음화된 활음을 생략한 표기와 풀어 쓴 표기 모두 허용 | jia 자/쟈/지아, jie 제/지에, xie 셰/씨에/시에 |
| 권설음·치경음 | zh/ch/sh/r과 z/c/s를 분류하고 가능한 후보를 유지 | zhi 즈/쯔/지, shi 스/시/쓰 |
| 특수 i | zhi/chi/shi/ri와 zi/ci/si의 i를 일반 i와 구분 | si 쓰/스, ji 지 |
| ü 계열 | j/q/x 뒤 u와 yu 계열의 생략된 점을 복원. nü/lü도 구분 | ju 쥐, qu 취, xu 쉬, zhu 주 |
| üan의 한글 표기 | 위안 표기를 유지하면서 웬/왠·위엔/위앤과 위/유 활음 표기를 공통 처리 | quan 췐/취엔/취앤/취안, juan 줸, xuan 쉔, yuan 웬/위엔 |
| ian·iong의 한글 표기 | 합쳐 쓴 활음과 풀어 쓴 활음을 함께 처리 | qian 첸/치엔/치앤, xiong 슝/숑/시웅/시옹 |
| 축약 운모 | iu/ui/un을 iou/uei/uen으로 복원. jun의 un은 ün으로 먼저 분류 | liu 류/리우, gui 궤이/구이, dun 둔/두언 |
| 영성모 | y/w를 독립 성모처럼 읽지 않고 원래 운모로 복원 | you 요우/유, wei 웨이, yuan 위안 |
| 비음 운미 | -n과 -ng를 별개로 유지 | an 안, ang 앙 |

위 표는 입력 허용 예시입니다. 발음 학습용 정밀 전사나 국립국어원 표준 표기법 전체의 구현이라고 주장하지 않습니다. 한글로 사라지는 성조와 음성 차이는 완전히 복원할 수 없습니다. 잘못된 발음을 반드시 원하는 단어로 보정해 주는 방식도 아닙니다.

역변환은 입력 전체를 병음 하나로 단정하지 않습니다. 음절 경계와 여러 독음을 남기는 제한된 탐색을 수행하고, 발음 형태의 비용·사전 단어·사용 빈도로 후보를 정렬합니다. 후보를 이동하면 해당 후보의 병음도 표시합니다. 이는 로컬 규칙과 사전 기반이며 학습된 AI 모델은 아닙니다. 입력이나 선택 이력은 학습·저장·전송하지 않습니다.

입력 전체가 병음 한 음절로 인식되는 경우, 각 독음의 대표 한자를 후보 안에 남깁니다. 예를 들어 퍄오가 biao/piao/fiao 여러 독음으로 해석될 때 빈도가 낮은 fiao의 한자가 다른 독음의 후보에 완전히 밀려 사라지는 것을 막습니다. 총 후보는 20개를 넘지 않으며 같은 한자는 중복 표시하지 않습니다.

## chi·qi처럼 한글 표기가 겹치는 경우

`chi`는 `츠·치`, `qi`는 `치`로 입력할 수 있습니다. `치판·츠판` 모두 `吃饭`을 후보로 표시하며, `치처`는 `汽车`를 표시합니다. `치`를 병음 하나로 고정하지 않습니다.

| 병음 | 기본 입력 | 추가 허용 입력 |
|---|---|---|
| zhi | 즈·쯔 | 지 |
| chi | 츠 | 치 |
| shi | 스·쓰 | 시 |
| ri | 르 | 리 |
| zi | 쯔·즈 | 지·찌 |
| ci | 츠 | 치 |
| si | 쓰·스 | 시·씨 |

추가 허용 입력은 편의용이며 표준 발음 표기와 다릅니다. 특히 `zi/ci/si`의 `지/치/시`는 기본 표기보다 낮은 발음 우선순위를 적용합니다. `치`에는 `qi/chi/ci`, `시`에는 `xi/shi/si` 후보가 함께 나올 수 있습니다. 입력 전체의 단어와 사전 빈도를 함께 보고 정렬하며, 한 음절 입력에서는 인식한 각 병음의 대표 후보를 남깁니다. 후보를 선택할 때 표시되는 병음으로 구분할 수 있습니다.

이 허용 규칙은 해당 음절에만 적용합니다. 모든 `이`를 `으`로 바꾸지 않으며, `ü/u`와 `n/ng`의 구분도 유지합니다.

표기 검토 자료: [국립국어원 중국어 표기법 세칙 검토](https://www.korean.go.kr/nkview/nklife/2008_4/2008_0402.pdf).

1.0.1에서는 발음 탐색에서 잘린 실제 사전 단어를 사전 접두사 경로로 복구합니다. 谁처럼 같은 한자에 여러 독음이 있으면 후보 행은 하나로 유지하고 `shui / shei`처럼 독음을 함께 표시합니다. 전체 점검 범위와 예시는 `AMBIGUITY_REVIEW.ko.md`를 확인하세요.

## 예시

니하오 → ni hao → 你好

셰셰 / 씨에씨에 → xie xie → 谢谢

워아이니 → wo ai ni → 我爱你

중궈 / 종궈 → zhong guo → 中国

베이징 → bei jing → 北京

짜이젠 → zai jian → 再见

니하오마 → ni hao ma → 你好吗

췐부 / 취엔부 → quan bu → 全部

안췐 → an quan → 安全

쉔저 / 쉬엔저 → xuan ze → 选择

숑마오 / 시옹마오 → xiong mao → 熊猫

표기 변형은 후보를 추가하는 규칙입니다. 예를 들어 ‘웬’은 wen과 yuan 양쪽 독음이 가능하므로, 단어와 빈도에 따라 후보 순서가 달라질 수 있습니다. -n/-ng, ü/u, quan/qun은 서로 다른 독음으로 유지합니다.

## 엔진과 범위

Microsoft Pinyin을 이 환경의 별도 TSF 문서에서 조회하는 시험에서는 후보를 얻지 못했습니다. `ITfFnSearchCandidateProvider` 조회는 E_NOINTERFACE였고, 프로필 활성화·IMM 변환 요청의 성공만으로 후보 생성을 확인할 수 없었습니다. 따라서 중국어 실사용 경로는 로컬 사전이며 Microsoft Pinyin 후보와 동일하다고 주장하지 않습니다. 일본어는 기존 Microsoft 일본어 IME 경로를 유지합니다.

사전은 Rime pinyin_simp의 수정하지 않은 원문 약 65,000개 항목을 사용합니다. 전체 단어가 없으면 병음 음절과 사전 단어를 조합합니다. 간체 중심 데이터이며 문맥 모델·사용자 학습·번체 전용 모드·성조 숫자 입력·얼화의 자동 복원은 이번 범위에 포함하지 않습니다. 사전과 라이선스·고정 리비전·해시는 `module/chinese_data/`에 있습니다.

입력 감지는 UI Automation 텍스트·커서, 표준 Windows Edit/RichEdit, UTF-8 Scintilla 경로를 공통 사용합니다. 상세 조건은 COMPATIBILITY.ko.md를 확인하세요. 메모장 본문에서 후보와 치환을 확인했습니다. 암호·읽기 전용 입력란과 텍스트 접근성을 제공하지 않는 앱, 더 높은 권한으로 실행된 앱에는 제약이 있습니다. 모든 앱 호환성을 보장하지 않습니다.

사전 준비와 검색은 별도 스레드에서 처리하고, 표시할 요청은 최신 것만 유지합니다. 입력은 최대 64개 한글 음절, 독음 탐색은 단계당 제한, 출력 후보는 최대 20개로 제한합니다. 앱 시작 후 사전을 미리 준비하며 OFF·일본어 전환 때에도 재사용합니다. 60ms 디바운스는 제거했습니다. 시작 직후 사전 준비가 끝나기 전에는 추가 대기가 발생할 수 있습니다.

- 사전 원본·Apache 2.0: https://github.com/rime/rime-pinyin-simp

검사: `Lexift.exe --verify-chinese 결과파일.json`

소스 검사: `python lab/pinyin_coverage_test.py` (전체 사전 음절의 역변환·대표 한자 후보와 추가 예시를 검사하고 위 두 병음 보고서를 갱신합니다.)
