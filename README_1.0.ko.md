# Lexift 1.0.0

KanaShift의 새 이름은 **Lexift**입니다. 기존 설정이 없는 첫 실행에서 KanaShift의 언어·단축키·입력기 슬롯·사용자 사전 설정을 가져오며, 기존 설정은 지우지 않습니다. 자동 실행을 사용하던 경우 새 실행 경로로 갱신하고 이전 자동 실행 항목의 중복을 제거합니다.

## 기능별 사용 여부와 사용자 사전

일반 설정의 **언어 스위칭** 박스에는 기존 입력기 선택 기능을, **한글 환경 언어 변환** 박스에는 두 발음 변환 기능을 배치했습니다. 각 단축키 옆의 **사용** 체크박스로 세 기능을 독립적으로 켜고 끕니다. 체크를 끄면 해당 단축키도 해제합니다. 설정은 다음 실행에도 유지됩니다. 트레이의 전체 ON/OFF는 세 기능의 설정을 보존한 채 일시정지합니다.

**사용자 사전** 메뉴는 원하는 이름이나 단어가 후보에 없을 때 사용합니다. **키워드 / 대치할 텍스트 / 언어**를 입력하고 저장하세요. 예: `스미네 / 澄音 / 한–일 변환`. 해당 언어 모드에서 입력 단위 전체가 키워드와 일치하면 등록 텍스트가 첫 후보로 표시됩니다. 기존 후보도 유지하며 자동으로 확정하지 않습니다. 언어별로 같은 키워드를 다르게 등록할 수 있습니다. 한글과 `-`로 된 키워드 최대 64자, 항목 최대 1,000개를 지원합니다.

프로그램의 일반 알림은 `module/Style/notify.wav`를 사용합니다. 시작·저장·오류·백그라운드 안내·업데이트 결과 등을 공통 경로로 연결하고, Windows 기본 풍선 알림음과 겹치지 않도록 앱 알림창을 재사용합니다. 일반 설정에서 알림음을 끌 수 있으며 음성 재생과 메뉴 처리는 별도 스레드에서 동작합니다.

표시 언어 9종에 변환 기능과 사용자 사전을 번역했습니다. 영어·일본어 UI에는 한국어 발음 입력용 기능이며 환경에 따라 지원하지 않을 수 있다는 안내를 표시합니다.

## 업데이트

업데이트 확인·다운로드 페이지는 https://github.com/luttechan/Lexift/releases 로 연결합니다. 정식 버전 번호는 `1.0.0`, 패키지 이름은 `Lexift-1.0.0-Windows-x64.zip`, 실행 파일은 `Lexift.exe`입니다. Lexift 패키지·매니페스트·업데이트 도우미의 이름을 일치시키고 다른 제품의 패키지는 설치하지 않습니다. 기존 KanaShift 바이너리를 실행한 상태에서는 중복 후크를 막기 위해 Lexift가 두 번째로 실행되지 않습니다.

0.7.9의 입력기 전환 기능·설정·애셋을 유지하면서, 다른 프로그램의 입력란에서 한글 발음을 일본어·중국어로 바꾸는 기능을 추가했습니다.

## 실행

정리된 최종 폴더에서는 `run.bat` 또는 `app/Lexift.exe`를 실행합니다. 배포 ZIP은 압축을 푼 뒤 `Lexift/Lexift.exe`를 실행하며 Python 설치가 필요하지 않습니다. 기존 실행 중인 버전을 종료한 뒤 Lexift 1.0을 실행하세요.

## 한–일 변환

1. **Caps Lock + A**: 한–일 변환 ON / OFF. 화면 하단에 상태를 표시합니다.
2. 켠 상태에서 메모장 등의 입력란에 `와타시`를 입력합니다. 별도 검색창을 열지 않습니다.
3. 커서 아래에 `わたし` 독음을 먼저 표시하고, Microsoft 일본어 IME가 생성한 `私`, `渡し` 등의 후보로 갱신합니다. 준비 중에도 독음을 선택해 입력할 수 있습니다.
4. ↑↓로 고른 뒤 **Space 또는 Enter**를 누르거나 후보를 클릭하면, 현재 입력란의 해당 발음만 일본어로 바꿉니다. 후보가 열린 상태의 Space는 공백을 추가하지 않고 선택을 확정합니다. 후보가 닫혀 있으면 일반 공백 입력입니다. Esc는 이번 후보만 닫습니다.
5. Caps Lock + Q는 기존 입력기 선택 기능입니다.

후보창의 **숫자 1~9**는 같은 번호의 행을 즉시 확정합니다. **0은 10번째 후보**입니다. 키보드 윗줄과 숫자 키패드 모두 지원합니다. 11번째 이후는 ↑↓와 Space/Enter 또는 클릭으로 선택합니다. 존재하지 않는 행 번호는 무시하며, 후보창이 닫혀 있으면 숫자를 평소대로 입력합니다. Ctrl·Alt·Shift 등을 함께 누른 숫자는 후보 단축키로 처리하지 않습니다. 일본어·중국어에 동일하게 적용합니다.

설정에서 입력기 전환·한–일 변환·한–중 변환 단축키를 각각 바꿀 수 있습니다. 세 단축키 중 두 개가 겹치면 적용 버튼을 비활성화합니다. Windows에 등록할 수 없는 조합은 저장하지 않고 이전 설정을 복구합니다.

한–일·한–중 모드는 **한국어 IME가 한글 상태인 경우에만** 켤 수 있습니다. 영어·일본어 등의 입력기, 한국어 IME의 영문 상태, 상태를 확인할 수 없는 입력란에서는 실행하지 않으며 IME를 강제로 변경하지 않습니다. 이미 켜진 기능을 끄는 동작은 다른 입력 상태에서도 허용합니다.

`모노즈쿠리 → ものづくり`, `츠즈쿠 → つづく`, `하나지 → はなぢ`처럼 관용 철자를 보정합니다. 한글 발음만으로 구별할 수 없는 `ず/づ`, `じ/ぢ`는 최대 8개 독음 대안으로 제시합니다. 모든 단어의 문맥을 추론하는 기능은 아닙니다.

## 한–중 변환

**Caps Lock + C**로 ON/OFF합니다. `니하오 → 你好`, `셰셰 → 谢谢`, `워아이니 → 我爱你`처럼 원래 입력란에서 후보를 고릅니다. 다른 언어 모드를 켜면 이전 모드는 꺼집니다. 중국어는 설치된 IME 대신 오프라인 병음 사전을 사용합니다. 한어병음 성모·운모·축약과 ü 규칙을 분류하고 여러 한글 발음 표기를 허용합니다. 상세 규칙과 범위는 [CHINESE_INPUT.ko.md](CHINESE_INPUT.ko.md)를 확인하세요.

## 지연 및 오류 수정

- 앱 시작 후 사용하도록 설정한 후보 엔진만 나누어 준비합니다. 모드 OFF 및 언어 전환 후에는 엔진을 재사용하되, 설정에서 기능의 사용 체크를 끄면 해당 엔진과 캐시를 해제합니다. 입력 감지는 모드를 켰을 때만 실행합니다.
- 60ms 디바운스를 제거하고 다음 Qt 이벤트 처리에서 최신 요청을 보냅니다. 입력 변경 이벤트와 짧은 폴링을 함께 사용하며, 표준 Windows 입력창은 UIA보다 먼저 직접 조회합니다. 이전 요청의 늦은 응답은 표시하지 않습니다.
- 후보와 독음의 글꼴을 제한된 CJK·기호 글꼴에서 선택하여, 이모지·희귀 한자·장음 기호 때문에 전체 설치 글꼴을 탐색하던 정지를 방지합니다.
- 설정 페이지는 한 번 생성해 재사용하고, 유휴 시간에 현재 창의 화면 영역만 최대 1280×900 픽셀로 제한해 준비합니다. 긴 스크롤 본문 전체나 사전의 모든 행을 미리 그리지 않습니다. 키보드 보조 프로세스의 시작 대기는 GUI 밖에서 처리합니다.
- 한 번에 도착한 입력 이벤트는 마지막 것만 표시합니다. 같은 독음을 이미 조회 중이면 요청을 다시 보내지 않으며, 언어별 최대 32개 결과를 OFF·언어 전환 후에도 재사용합니다. 캐시는 메모리에만 두고 앱 종료 시 비웁니다.
- 커서 좌표가 없다는 이유로 정상 텍스트까지 거부하던 경로를 수정했습니다. UIA·Windows 커서·MSAA 좌표를 사용하고, 정확한 커서 정보를 제공하지 않는 입력창에서는 입력창 바로 아래에 후보를 표시합니다. 위쪽 모니터의 0·음수 좌표도 허용합니다.
- 후보 계산용 문서는 표시하지 않는 별도 데스크톱에서 실행하여, 입력 중인 프로그램의 포커스를 가져가지 않습니다.
- 후보가 열린 상태에서도 일반 글자와 숫자는 원래 프로그램으로 전달합니다. Space와 Enter는 선택한 후보를 확정합니다.
- 다른 창으로 이동하면 후보를 숨기고 방향키·Enter 처리를 해제합니다. 치환 직전에도 창·입력 컨트롤·원문·커서 위치를 다시 확인합니다.
- Windows 폰트 초기화 경로를 통일하고, 서로 다른 DPI 모니터에서 후보 위치를 해당 모니터 기준으로 계산합니다.

## 다른 프로그램에서의 사용과 호환성

Windows 10/11이 필요하며, 일본어 변환에는 Microsoft 일본어 IME가 필요합니다. 중국어 변환은 중국어 IME 설치 없이 실행됩니다. 입력란은 UI Automation 텍스트/커서 인터페이스, 표준 Windows Edit/RichEdit 또는 UTF-8 Scintilla 경로 중 하나로 처리합니다. [호환성 안내](COMPATIBILITY.ko.md)를 확인하세요. 메모장 본문에서 후보 표시와 원문 치환을 검증했습니다. 모든 앱의 호환성을 보장하지는 않습니다. 텍스트 접근을 제공하지 않는 게임·사용자 정의 편집기, 암호 입력란, 읽기 전용 입력란, 더 높은 권한으로 실행된 앱은 지원이 제한됩니다.

브라우저 등 여러 프로세스로 구성된 앱은 입력 컨트롤의 접근성 계층을 확인하도록 구현했습니다. 앱별 추가 검증이 필요합니다. 중국어는 로컬 병음 사전의 간체 후보를 사용합니다.

실행 중 발음과 후보는 메모리에서만 처리하며, 일반 실행에서 입력 내용을 파일에 기록하지 않습니다. 진단 결과는 별도 진단 명령에서만 저장합니다.

## 검증 결과

회귀 테스트 398개와 IAccessible2 어댑터 21개 검사를 사용합니다. 새 다중 독음 엔진은 실제 IME 18개 사례에서 목표 후보를 모두 찾았습니다. 첫 조회 274ms, 이후 첫 응답 57~200ms였으며, 대체 독음 전체 조회는 최장 약 2.7초로 첫 응답과 별도로 진행됐습니다. 0.1초를 모든 한자 조회의 보장 시간으로 제시하지 않습니다. 기존 자체 Edit 창의 독음 미리보기 측정은 약 8~26ms, 중국어 후보 약 6~29ms였으며 이 자료는 이전 표시 경로의 측정 기록입니다. 새 후보 위치 계산은 모니터 배율·음수 원점·화면 경계 테스트로 검사했습니다.

측정은 자체 입력창의 문자열을 변경하는 개발 검사입니다. 앱 시작 직후 엔진 준비 시간, 물리 키보드의 한글 조합 중 노출 여부, 다른 앱의 접근성 응답 시간은 별도이며 모든 환경에서 0.1초를 보장하지 않습니다. 메모장 본문 치환과 중국어 니하오→你好 치환은 기존 검증을 유지했습니다. 현재 입력란의 한국어 IME 영문→한글 전환도 자체 입력창에서 확인했습니다. 별도 영어 레이아웃→한국어 전환은 상태 변화 모의 검사로 검증했습니다.

## 검증 자료

- `test-results/regression-0.8-final.txt`: 회귀 테스트
- `test-results/query-benchmark.json`: 실제 IME 엔진 지연 측정 (초기 준비 시간 별도)
- `test-results/latency-desktop.json`: 자체 입력창의 첫 화면·전체 후보 표시 및 영문→한글 전환 검사
- `test-results/preferences-latency-after.json`: 일반 설정 페이지 전환 측정
- `test-results/frozen-ime-final.json`: 배포 실행 파일의 Qt/IME 연결 검사
- `test-results/inline-notepad-verified.json`: 메모장 본문 치환 검증

검사 명령: `Lexift.exe --verify-ime 결과파일.json`

중국어 검사 명령: `Lexift.exe --verify-chinese 결과파일.json`

긴 문장 Space 확정 수정: 모요-데스 → 模様です, 센세-데스 → 先生です, 코-죠-데스 → 工場です를 검사했습니다. 텍스트와 입력 위치가 그대로인 좌표 변경은 확정을 취소하지 않으며, 같은 독음의 후보 갱신에서도 선택한 행을 유지합니다. 입력 원문·범위·포커스가 달라지면 오래된 확정 요청은 계속 거부합니다.

Space 전용 후크 보강: IME 처리 키(VK_PROCESSKEY)의 스캔 코드가 Space이면 일반 Space와 같은 상태로 처리합니다. IME가 만든 키 해제도 누른 상태를 해제하며, 다음 발음 입력은 이전 Space의 누락된 해제 상태를 정리합니다. 길게 누르기의 중복 확정은 억제합니다. 네이티브 이벤트 처리 회귀 테스트를 추가했습니다. 메모장에서는 고치소-사마의 후보 생성과 확정 명령에 따른 ご馳走様 치환을 확인했습니다. 이 자동화 검사는 사용자의 물리 키보드 이벤트 자체를 재현한 검사는 아닙니다.

발음 변환 구조 개선: 최대 16개 독음을 비용 순서로 실제 IME에 조회하며, 첫 결과부터 표시하고 최종 결과만 캐시합니다. `じ/ぢ`, `ず/づ`, 장음, 쯔/츠, 일부 청음·탁음 대안, 어간의 철자 보정과 조사 해석을 처리합니다. 문절 후보는 전체 조합 문자열과 합쳐 어미·다른 단어가 사라지지 않게 합니다. 후보별 실제 조회 독음도 표시합니다. 상세 범위와 한계는 HANGUL_READING.ko.md를 참조하세요.

입력 위치와 Firefox 호환 경로: 커서·글자 위치를 우선 사용하고 좌표가 없으면 입력칸 가까이에 표시합니다. Firefox용 MSAA/IAccessible2 입력 감지·범위 치환을 추가했습니다. 자체 COM 제공자 검증은 통과했으며 실제 Firefox 종단 검사는 수행하지 않았습니다. 관련 자료는 COMPATIBILITY.ko.md에 기록했습니다.

연속 Space와 후보 스크롤 수정: 확정 요청을 한 번만 보내고 응답 전에는 같은 입력의 후보 재표시·중복 확정을 막습니다. 대상 앱에 공백 키를 전달해 한글 조합을 먼저 완료하고, 정확히 추가된 한 공백과 원문을 재검증한 범위만 후보로 치환합니다. 방향키·Home·End로 커서를 옮기지 않습니다. IA2 치환 후에는 커서를 치환 문자열 뒤에 둡니다. 확정 중 빠른 추가 Space는 중복 명령으로 처리하지 않습니다. 새 입력과 자동 미리보기 갱신은 후보 1부터 표시하며, 사용자가 명시적으로 고른 후보만 다음 갱신에서 유지합니다.

메뉴 지연 개선: 숨겨진 설정 페이지 전체를 grab으로 그리는 작업을 제거하고 일반 설정·정보 페이지를 유휴 시간에 나누어 준비합니다. 입력 감지기는 Lexift 본체 PID를 제외하며, 일시정지 시 텍스트 폴링과 진행 중인 후보 검색도 멈춥니다. 같은 후보 목록은 다시 만들지 않으며 화면이 이미 보이는 갱신에서는 반복적으로 최상단 창 올리기와 단축키 보조 IPC를 보내지 않습니다. 메뉴 개발 측정은 test-results/menu-latency-final.json에 기록했습니다.


최종 릴리즈 점검: `--verify-settings 결과파일.json`으로 9개 표시 언어에서 설정값 저장, 기능별 스위치, 단축키 중복 차단, 사용자 사전, 화면 이동과 표시 시간을 확인할 수 있습니다. 실제 사용자 설정과 키보드 후크는 변경하지 않습니다. 사이드바·대시보드·프로그램 정보에 `Style/Lexift_black.png` 원본 로고를 사용합니다.
